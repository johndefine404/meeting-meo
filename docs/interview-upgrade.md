작성 2026-10-16. 대상 브랜치 interview-upgrade.

## 1. 목표

- 면접 모드를 "면접 중 답을 띄워 주는 화면"에서 "합격률을 올리는 준비, 연습, 복기 도구"로 바꾼다.
- 한 번 쓰고 끝나는 도구가 아니라, 면접을 볼수록 답변과 배운 점이 쌓이는 도구로 만든다.
- 무료 오픈소스 판으로 끝까지 쓸 수 있게 하고, 유료 판은 그 위에 얹는 구조로 둔다.

## 2. 무엇이 합격률을 움직이나 (근거)

근거 강도는 세 단계로 적는다. 강함 = 학술 연구가 반복해 확인, 중간 = 연구 하나 또는 간접 근거, 약함 = 업계 설문·경험칙.

| 요인 | 근거 | 강도 | 제품에 주는 뜻 |
|---|---|---|---|
| 면접 코칭과 준비 | Maurer 외(1998, 2001, Journal of Applied Psychology): 코칭을 받고 준비 전략을 쓴 지원자가 구조화 면접에서 더 높은 점수를 받았다 | 강함 | 예상 질문, 답 구조, 연습이 핵심 기능이다 |
| 구조화 면접의 채점 방식 | McDaniel 외(1994) 메타분석 등: 구조화 면접이 더 타당해 기업이 많이 쓴다. 면접관은 역량별 기준표로 채점한다 | 강함 | 답을 "면접관이 보는 기준"에 맞춰 짜고, 그 기준으로 채점하는 연습이 맞다 |
| 면접 불안 | 면접 불안과 면접 점수 사이 메타분석 상관 약 -.19 | 중간 | 반복 연습으로 익숙하게 만드는 것, 미팅 중 화면을 조용하게 두는 것이 중요하다 |
| 첫인상과 초반 라포 | Barrick, Swider, Stewart(2010, JAP): 초반 라포 단계 평가가 최종 점수(r=.42), 실제 제안(r=.22)과 이어졌다 | 강함 | 자기소개 1분과 첫 3분을 가장 많이 연습하게 한다 |
| 소리 내어 떠올리는 연습 | 인출 연습 효과(Roediger, Karpicke 2006): 다시 읽기보다 떠올려 말하기가 오래 남는다 | 중간(면접 직접 연구 아님) | 답을 읽게 하지 말고, 질문만 보고 말하게 한 뒤 채점한다 |
| 대본 읽기 | 직접 연구 없음. 비언어 행동(시선, 유창함)이 평가와 이어진다는 연구(DeGroot, Motowidlo 1999)에서 추론 | 약함 | 면접 중에는 문장 대본보다 핵심어 몇 개를 띄운다 |
| 감사 메일 | 채용 담당자 설문 위주 | 약함 | 만들어는 주되 핵심 기능으로 내세우지 않는다 |

결론:
- 가장 큰 효과는 면접 전에 난다. 예상 질문에 내 사실로 답을 짜고, 소리 내 연습하고, 채점받는 것.
- 면접 중 화면은 기억을 깨우는 핵심어와 위험 경고만 조용히 띄운다. 긴 문장을 읽게 만들면 오히려 손해다.
- 면접 후 복기는 다음 면접 준비의 재료가 될 때만 의미가 있다. 그래서 기록장이 필요하다.

## 3. 기능 목록과 우선순위

P0 = 이번에 만든다. P1 = 다음 차례. P2 = 유료 판 후보.

### 면접 전

| 기능 | 우선 | 판단 |
|---|---|---|
| 면접 준비 키트: 한 줄 메시지, 면접관이 볼 기준, 예상 질문과 답, 곤란한 질문 방어, 내가 물어볼 질문, 말하지 않을 것, 시간 배분 | P0 | 사람이 손으로 짠 강한 면접 준비 문서의 구성이다. 이걸 자동으로 만든다 |
| 답은 이력서 사실만으로, 모르는 곳은 ○○로 비움. 쓴 사실을 답마다 붙여 둠 | P0 | 지어낸 경험은 꼬리 질문 한 번에 무너진다. 근거를 보여 줘야 사용자가 믿고 고친다 |
| 곤란한 질문(공백, 직함 차이, 거주지·비자, 처우, 이직 사유) 방어 답과 피할 말 | P0 | 탈락은 대개 여기서 난다 |
| 처우 하한 같은 내부 기준은 답에 절대 넣지 않음 | P0 | "지켜야 할 선"에 적은 숫자가 입 밖으로 나가면 협상이 끝난다 |
| 연습 모드: 질문을 보고 말하거나 써서 답하면 4개 기준으로 채점, 더 나은 답, 꼬리 질문 | P0 | 근거가 가장 강한 기능이다 |
| 음성 연습: 맥 마이크로 답하면 맥 안에서 받아쓰고 채점 | P0 | 말로 하는 연습이어야 실제와 가깝다. 받아쓰기는 기존 엔진을 그대로 쓴다 |
| 회사 조사: 공고·홈페이지 주소 읽기 | 이미 있음 | 기존 기능을 그대로 쓴다 |
| 면접관 개인 조사(링크드인 등) | P2 | 로그인 벽과 개인정보 문제가 있다. 사용자가 붙여 넣은 글만 쓴다 |
| 검색으로 회사 뉴스·투자 소식 넓게 모으기 | P2 | 검색 API 비용이 든다. 유료 판 후보 |

## 4. 무료와 유료 나누기

무료(오픈소스, 본인 키):
- 위 P0 전부. 데이터는 전부 사용자 맥에만 둔다.
- 비용은 사용자 AI 키로 나간다. 준비 키트 1회, 연습 채점 1회당 1번 호출.

유료 판 후보:
- 키 없이 쓰기(우리가 AI 비용을 대고 월 구독).
- 음성 모의 면접관: 질문을 소리로 읽어 주고, 대화를 이어 가는 실전형 연습.
- 회사·직무 조사 확장: 검색으로 뉴스·투자·채용 이력까지 모아 정리.
- 직무별 질문 묶음과 채점 기준(개발, 디자인, PM, 영업 등)을 사람이 다듬어 제공.
- 기기 간 동기화와 기록장 백업.
- 면접 결과와 답의 관계 분석: 어떤 답이 다음 단계로 이어졌는지.
- 사람 코치의 녹취 검토(선택).

나누는 원칙: 합격률에 직접 효과가 있는 준비, 연습, 복기 기본은 무료로 둔다. 비용이 우리에게 드는 것(키 대행, 검색, 음성 합성)과 사람 손이 드는 것만 유료로 한다.

## 5. 데이터 구조

저장 위치는 데이터 폴더(기본 `~/Library/Application Support/meeting-meo`, 환경 변수 `MEETING_MEO_DATA`로 바꿀 수 있음) 안 `interview/bank.json` 하나다.

```json
{
  "answers": [
    {"id": "a1b2", "qtype": "지원 동기", "question": "왜 지원하셨나요",
     "answer": "두 가지입니다. ...", "cue": "예약 앱 출시 · 고객 인터뷰 ○○건 · 끝까지",
     "facts": ["예약 앱 기획부터 출시까지 담당"], "gaps": "", "dont": "", "company": "느린곰랩",
     "source": "준비", "updated": "2026-10-16 15:00", "scores": [{"date": "2026-10-16", "total": 72}]}
  ],
  "lessons": [{"text": "처우는 세후로 먼저 말하고 세전 환산을 준비", "date": "2026-11-02", "from": "느린곰랩"}],
  "history": [{"id": "20261102-140000", "company": "느린곰랩 · 면접", "date": "2026-11-02", "result": "대기"}]
}
```

- 질문 종류는 고정 목록이다: 자기소개, 지원 동기, 이직 사유, 강점, 약점, 성공 경험, 실패 경험, 갈등·협업, 리더십, 직무 역량, 기술 질문, 처우, 입사 시기, 근무 형태, 공백·경력 전환, 마지막 한마디, 기타.
- 하나만 두는 종류(자기소개, 지원 동기, 처우 등)는 같은 종류끼리 덮어쓰고, 여러 개 두는 종류(성공 경험, 기술 질문, 공백·경력 전환 등)는 질문 글이 같을 때만 덮어쓴다.
- 지원 동기, 마지막 한마디처럼 회사마다 달라지는 답은 `company`(어느 회사 면접용인지)를 달아 둔다. 다른 회사 답을 덮어쓰지 않고 따로 남긴다.
- 저장할 때 `id`가 오면 그 항목만 고친다. 빈 값으로 기존 값을 지우지 않는다.
- 지켜야 할 선에 적은 숫자(두 자리 이상이거나 만·원·% 같은 단위가 붙은 것)는 준비 키트, 미팅 중 카드, 경고, 연습의 더 나은 답에서 ○○로 가린다. 미팅 후 돌아보기에는 실수를 보여 주려고 그대로 둔다.
- 미팅별 준비 키트는 기존처럼 `meetings/{id}/meeting.json`의 `prep.interview`에, 복기는 `after.json`의 `debrief`에 둔다.

## 6. 사용 흐름

면접 전:
1. 준비 화면에서 "면접"을 고르고 이력서, 공고 주소, 목표, 지켜야 할 선(처우 하한 등)을 넣는다.
2. "준비 자료 만들기"를 누르면 준비 자료 아래에 면접 키트가 붙는다. 기록장에 답과 배운 점이 있으면 그걸 바탕으로 만든다.
3. 답을 눌러 고치고, "답변 은행에 저장"으로 기록장에 넣는다.
4. "연습하기"로 예상 질문을 하나씩 소리 내 답하고 채점받는다. 더 나은 답은 은행에 저장한다. 꼬리 질문으로 이어서 연습한다.

면접 중:
1. 질문이 오면 위 카드에 질문 종류와 내가 다듬은 핵심어가 크게 뜬다. 추천 답 한 문장은 그 아래다.
2. 곤란한 질문이면 피할 말이 빨갛게 뜬다. 내가 선을 넘는 말을 하면 경고가 뜬다. 내 말은 추천 답 카드를 다시 만들지 않고, 가벼운 점검만 따로 돈다. 지켜야 할 선의 숫자를 그대로 말하면 AI를 부르지 않고 바로 알린다.
3. 폰 프롬프터로 보면 핵심어만 크게 보인다.

면접 후:
1. "미팅 끝내고 정리하기"를 누르면 기준별 점수, 질문별 돌아보기, 잘한 것과 고칠 것, 감사 메일이 나온다.
2. 마음에 드는 더 나은 답을 고르고 "다음 면접에 가져가기"를 누르면 기록장에 들어간다.
3. 결과가 나오면 기록장에서 결과를 고른다.

## 7. 지키는 선

- 사실만 쓴다. 이력서에 없는 경험, 숫자, 속마음은 ○○로 비운다. 채점의 "더 나은 답"도 같다.
- 지켜야 할 선에 적은 내부 기준은 어떤 답에도 넣지 않는다.
- 받아쓰기 동의를 먼저 구하라는 안내는 그대로 둔다.
- 연습 음성은 맥 안에서만 받아쓰고 버린다.

## 8. 이번에 만들지 않은 것

- 음성 모의 면접관(질문을 소리로 읽어 주기), 검색 기반 회사 조사, 결과 분석: 유료 후보로 남긴다.
- 영업·회의 모드의 기록장: 구조는 같게 쓸 수 있지만 이번 범위가 아니다.
